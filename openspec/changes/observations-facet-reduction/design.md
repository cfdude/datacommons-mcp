## Context

`get_observations_paginated` (services/observations.py:330) builds an `ObservationRequest` via `_validate_and_build_request`, calls `client.fetch_obs_page(request)` (which passes `filter_facet_ids=request.source_ids` to the v2 API, clients/observations.py:36/42), then `_build_final_response` → `_process_sources_and_filter_observations` (services/observations.py:140). That function: with `source_override`, early-returns filtering to that facet per place (lines 149-167); else ranks all facets globally by `(place_coverage, total_obs_count, latest_date, -avg_facet_index, src_id)` (199-211) and keeps ONLY the primary source per place, **dropping places without it** (222-232). So the rendered output is already "one source per place, places lacking the primary excluded."

The v2 API has no pagination (confirmed against REST + Python v2 docs and live) and hard-rejects >~tens-of-thousands of series with HTTP 500. The memory cost is the multi-facet raw response (~11× the written rows). `filter_facet_ids` lets the API return a chosen facet only — measured ~10× memory reduction, identical output (since today already collapses to one primary).

## Decisions

**1. Auto-select = "compute the primary facet cheaply, then filtered-fetch + reconstruct from the kept probe."** For a `child_place_type` + `date="all"` (`date_filter is None`) + no-override query: (a) probe at `date="latest"`, rank facets, pick primary, AND keep the probe's full place set + per-source coverage; (b) set `request.source_ids=[primary]` → `fetch_obs_page` sends `filter_facet_ids=[primary]`; the lib auto-routes `_process_sources_and_filter_observations` through the override branch because `source_override = request.source_ids[0] if request.source_ids else None` (services/observations.py:274) — so no separate `source_override` threading is needed. **(c) Reconstruct from the probe** — the override branch alone is NOT output-equivalent: VERIFIED LIVE that `filter_facet_ids` returns ONLY places with the primary facet (3,232 of 3,237 counties; the 5 without it are dropped), and the override branch returns `alternative_source_counts={}`. Today's non-reduced path re-adds every place with an empty time-series (`_build_final_response` 299-310 via `_create_place_observation(None)`, asserted at test_services.py:402-412) and populates `alternative_sources` (asserted 415-417). So pass the probe's `(full_place_dcids, alternative_source_counts)` into `_build_final_response` and have it re-add the empty-series places + populate `alternative_sources` in the reduced path — making output identical to today modulo only the tiebreak caveat. *Why keep the probe:* it's a full multi-facet `latest` fetch whose `byEntity.keys()` is exactly today's full place set (coverage-at-latest ≡ coverage-at-all), so it carries everything needed to reconstruct faithfully. Extract just `(place set, per-source counts, primary)` (small — KB) and discard the probe response so retention stays bounded.

**2. Probe at `date="latest"`, full default select.** Returns one obs per place per facet — small (~21 MB measured) and parseable (reduced `select` breaks the lib's typed model — verified, so do NOT use it). Coverage at `latest` == coverage over `all` (a facet covers P at latest iff it has any data for P), so the place-coverage primary is faithful; only the obs-count tiebreaker is lost.

**3. Extract the ranking into a shared helper.** Pull the stats-gather + `max(...)` (169-211) into `rank_primary_facet(variable_data: ByVariable, date_filter) -> str | None`. The probe calls it on the `latest` response; `_process_sources_and_filter_observations` calls it on the full response. One implementation, no drift.

**4. Scope: `child_place_type` AND `date="all"` AND no `source_override`.** The EXACT gate (C5) is `request.date_type == ObservationDateType.ALL and request.date_filter is None and request.child_place_type and not request.source_ids` — because `_validate_and_build_request` sets `date_type=ALL` with a non-None `date_filter` for BOTH a single date (73-75) and a range (67-69); only true `date="all"` has `date_filter is None`. Single-place (no fan-out, tiny), explicit override (facet known), single-date and ranges skip the probe. Date RANGES are excluded: the `latest` probe's coverage can mismatch a range-filtered ranking (a facet whose latest obs falls outside the range would be miscounted). Ranges keep current behavior; users can pass `source_override`.

**6. Probe runs AFTER the size guardrail (C3).** The `latest` probe itself fans out all places, so it 500s for beyond-cap geographies. The guardrail (services/observations.py:370-386) must execute BEFORE the probe so a doomed (over-`max_places`) query is refused cleanly with `ResultTooLargeError` and NEVER issues a probe fetch. Insert auto-select strictly between the guardrail and the main fetch.

**5. Raise `DC_MAX_PLACES` default 1000 → 5000.** Memory dropped ~10×, so county-scale (~3,238) is now safe (~148 MB). 5000 places × 1 var = 5000 series, far under the ~tens-of-thousands series cap. The guardrail's purpose shifts from memory→series-cap; A-ii (sharding) removes it entirely for beyond-cap geographies.

## Risks / Trade-offs

- **Coverage-tie fidelity (the one accepted behavior change).** When sources tie on place-coverage, the probe lacks obs-count, so the tiebreak falls to latest-date/facet-order → may pick a different (equally-covering) source than today. Documented; `source_override` is exact. Perfect parity needs the full multi-facet pull (the thing we avoid). Secondary (C6, smaller): `avg_facet_index` depends on `orderedFacets` position; if the API orders facets differently between the `latest` probe and an `all` fetch, that tiebreaker could diverge too — same coverage+latest-date pre-condition, low likelihood (provenance ordering is stable). Both are sub-tiebreaker effects only.
- **C4 — the `DC_MAX_PLACES`→5000 raise re-exposes UNREDUCED queries.** Auto-reduction is only `date="all"`. A single date (tiny) and a date RANGE both run at `date=ALL`+`date_filter` server-side (all facets, all dates, narrowed in memory) — NOT reduced. So a WIDE range over up to 5000 places can approach the old heavy profile. Accepted + documented (proposal + docs); the cap raise is justified for the common reduced (`all`) and tiny (`latest`/single-date) cases; wide-range-many-place exports stay heavy until A-ii (sharding). (Not adding a separate sub-cap in A-i — keep it simple; A-ii is the real fix.)
- **Two API calls** for the auto case (probe + filtered). Probe is cheap; the filtered main call is ~10× smaller, so net memory win and usually net time win vs one full call.
- **A-i does NOT bypass the series cap.** The `latest` probe itself fans out all places → it 500s for tract-scale just like the full query. So A-i helps only within the cap (county/state). Beyond-cap = A-ii (shard the places, incl. the probe). The C guardrail still protects the boundary.
- **Dead pagination code** (`fetch_obs_page` page_token, `_extract_next_token`, the token in `get_observations_paginated`) is confirmed inert on v2. Leave it for A-ii (which rewrites the fetch path) rather than churn it here — note only.

## Migration Plan

1. `services/observations.py`: extract `rank_primary_facet(variable_data) -> (primary_id, per_source_counts)` from `_process_sources_and_filter_observations`; have that function call it. In `get_observations_paginated`, AFTER the guardrail (C3) and only when the C5 gate holds: probe (`date="latest"` request → `fetch_obs_page` → `rank_primary_facet`), keep `(full_place_dcids, alternative_source_counts, primary)`, set `request.source_ids=[primary]`, do the main fetch, and pass the kept probe data into `_build_final_response` so it re-adds empty-series places + populates `alternative_sources` in the reduced path (probe-carry-forward). `get_observations` (non-paginated) is NOT modified (the tool uses the paginated path).
2. `config.py`: `DC_MAX_PLACES` default → 5000.
3. Tests (unit + service-level with mocked client returning a multi-facet `latest` probe response then a single-facet full response): ranking helper; auto-select; **place-membership equivalence** (reduced result has the SAME place set incl. empty-series places); **`alternative_sources` preserved**; probe-after-guardrail (zero probe when refused); single-date/range/override/single-place → no probe; coverage-tie. Plus `docs/reference.md`.
