## Context

Flow today: `tools/observations.py::get_observations` → `get_observations_paginated` (validates, runs the C guardrail via `count_child_places`, A-i facet-reduction, fetches, materializes ONE `ObservationToolResponse`) → `output_handler.handle_observations` (routes screen vs file by row count) → `_handle_file_output` → `pagination_handler.fetch_with_auto_streaming` → `CSVStreamer`. `CSVStreamer` (csv_streamer.py) is a context manager whose `write_response_page(response, page_number)` appends incrementally and is shard-ready as-is. `client.fetch_obs`/`fetch_obs_page` already branch `fetch_observations_by_entity_type` (child) vs `fetch(entity_dcids=...)` (explicit) — both accept `filter_facet_ids`. Investigation facts in [[observations-streaming-reality]].

## Decisions

**1. Route by child count; `DC_MAX_PLACES` becomes a shard trigger.** For a `child_place_type` query: `n` (the enumerated child count); `n > DC_MAX_PLACES` → `ResultTooLargeError` (absolute ceiling); `DC_SHARD_SIZE < n ≤ DC_MAX_PLACES` → **sharded export**; `n ≤ DC_SHARD_SIZE` → existing A-i single fetch (unchanged). Config: new `DC_SHARD_SIZE` (default 15000); raise `DC_MAX_PLACES` default to **150000** to admit all-US-tracts (≈97,659) with headroom — **and raise the field bound `le` 100000 → e.g. 1000000 in lockstep (Gate-1 C1: the current `le=100000` makes a 150000 default/ceiling unsettable)**. `DC_SHARD_SIZE` doubles as the non-sharded materialization ceiling (≤ it → one A-i fetch): justified because a facet-reduced single fetch of 15000 places ≈ one shard's footprint (~226 MB measured at 15-20k), i.e. bounded and safe — the same memory whether it's "one A-i fetch of 15k" or "one shard of 15k". Add a `model_validator` enforcing `shard_min ≤ shard_size ≤ max_places` (M4).

**2. Reuse the existing file path via a PAGE-PRODUCER — do NOT build a parallel driver (resolves Gate-1 I1).** `_handle_file_output` already builds the full `ObservationsFileResult` (incl. the A-i `preview`/`summary`/`columns`, `format`, `multi_file`, `file_size_bytes`, `unique_places_count`). A second driver would re-implement all of that and drift (A-i just added `preview`). Instead, generalize the file path to consume an **async iterator of `ObservationToolResponse` pages**: the normal path yields ONE page (today's behavior); the sharded path yields N pages (one per shard). `_handle_file_output` opens the `CSVStreamer` once, `write_response_page` for each yielded page, and constructs the result ONCE (preview from the first page). Extract a shared `_finalize_file_result(...)` if cleaner. Net: one result-construction code path, sharded or not. (`CSVStreamer` is already incremental — `_headers_written` guard means headers write once; verified.)

**3. Facet from a SPREAD sample, reused for all; coverage measured against the REQUESTED shard and surfaced (resolves C2 + I3).** A full all-facets probe over ALL places would exceed the cap, so probe a sample at `date="latest"` (all facets) → `rank_primary_facet` (shared with A-i) → primary, then `filter_facet_ids=[primary]` for every shard. **The sample is SPREAD across the geography** (e.g. `dcids[::stride]` up to `shard_size`), NOT the first contiguous shard — enumeration is geoId-clustered (state-ordered), so a contiguous first shard is regionally biased exactly for the regionally-sourced variables the guard protects. **Coverage guard:** for each shard, coverage = `(places the primary actually returned) / len(requested shard)` — NOT over returned places (filtering to the primary makes that ~100% always, a no-op). If coverage `< DC_SHARD_FACET_MIN_COVERAGE` (default 0.8) on any shard, accumulate the shortfall. **Surface it in the result** (a `places_missing: int` / coverage note on `ObservationsFileResult` AND in `summary`) — the consumer is an LLM agent that never sees `logger.warning`, so a log alone is invisible. `source_override` forces an explicit facet and skips the probe.

**4. Single service-level orchestrator counts/enumerates ONCE (resolves I2).** Routing lives in ONE service entry, not split tool/driver. It calls `fetch_child_place_dcids` once (the DCID list; `count = len(...)`), then dispatches: `count > max_places` → refuse; `count > shard_size` → shard (the page-producer over the already-enumerated DCIDs); else → A-i single fetch. This avoids the tool counting + the driver re-enumerating (`count_child_places` would otherwise fetch `fetch_place_children` twice). `get_observations_paginated` keeps its own guardrail for its direct/test callers. NOTE: `ObservationRequest` has **no `entity_dcids` field** — the shard fetch calls the new client method directly with the shard list and reuses `_build_final_response` by passing the parent request with `source_ids=[primary]` (which routes through the `source_override` branch at services/observations.py:203). Per shard: `fetch_observations_by_entity_dcid(shard, [primary], date)` → `_fetch_all_metadata` for the shard → `_build_final_response` → small `ObservationToolResponse` → yield it → drop the reference. **No empty-series / `alternative_sources` reconstruction** — a file export emits zero rows for places without the primary source.

**5. Adaptive retry: halve on size-error, write each LEAF (resolves I4).** `fetch_shard(shard)` yields processed pages: try `fetch_observations_by_entity_dcid(shard, [primary], date)`; on `DCStatusError` with `status_code in (500, 502)` (the only distinguishable signal — a generic 500 is indistinguishable by reason, so the `DC_SHARD_MIN` floor + clear error IS the safety; stated honestly), split the shard in half and recurse on each half. Each LEAF sub-shard is fetched → processed → written as its own page (the streamer accumulates) — **nothing is concatenated/merged**. Floor at `DC_SHARD_MIN` (default 1000): a floor shard that still fails raises a clear error naming the variable+size. **Apply MUST verify** a 502 surfaces as `DCStatusError` (an `HTTPError`, request_handling.py:120) and not a raw `requests.exceptions.Timeout` (a sibling the lib's `except HTTPError` net does NOT convert) — if it escapes, widen the catch.

**6. `ObservationsFileResult`** + a `places_missing: int` field (I3 — coverage shortfall surfaced to the agent, also mentioned in `summary`); `rows_written` summed across shards; `preview`/`summary` from the first page; `pages_fetched` set to the **number of shard fetches** (honest; pinned by a test — M7). `multi_file` companion-file export is **NOT supported on sharded exports** (undesigned over N shards) — assert it's off/ignored for the sharded path (M6).

**7. Remove ONLY the dead pagination code (M1 — `_stream_to_file` itself is LIVE).** `_handle_file_output` always calls `fetch_with_auto_streaming(force_file=True)`, and v2 `next_token` is always `None`, so control always falls through to `_stream_to_file` — the live single-page file path that MUST keep working. Remove only the unreachable `while next_token` loop (pagination_handler.py:217-231) and `_write_api_response_page` (244+). Add a test proving the single-page (≤shard-size) file export still writes.

## Risks / Trade-offs

- **502 wall is variable-dependent, not a constant** → conservative `DC_SHARD_SIZE` + adaptive halving (Decision 5) is the real safety; `DC_SHARD_SIZE` is a starting point, not a guarantee.
- **Regional-variable facet coverage** (Q4 unverified for non-census vars) → spread-sample facet probe (Decision 3, less geo-biased than a contiguous first shard) + a coverage guard whose shortfall is **surfaced in the result** (`places_missing` + `summary`), so the agent sees it (not just a log) + `source_override`. A future option: per-shard facet selection (rejected for v1 — inconsistent sources across one file).
- **NOT a new parallel write path** → the file path is generalized to a page-producer and reused (Decision 2); sharded and single-fetch share one `ObservationsFileResult` construction, so they can't drift.
- **Wall-clock** for the largest exports is minutes (~5-7 shards × seconds), not memory-bound. `DC_MAX_PLACES` caps the absurd.
- **Multi-variable** sharding not investigated → single-variable scope; note as follow-up.
- **"O(shard)" is approximate** (M3): `CSVStreamer._stats.unique_places` is a `set` that grows O(total places) (a few MB at 97k) + the enumerated DCID list (a few MB). Both small and constant-factor; peak working set per fetch is still O(shard).

## Migration Plan (staged)

1. Client: `fetch_observations_by_entity_dcid(variable_dcid, entity_dcids: list[str], date, filter_facet_ids)` (clients/observations.py); `fetch_child_place_dcids(parent, child_type) -> list[str]` (clients/entities.py; `count_child_places` reuses it).
2. Config: `DC_SHARD_SIZE` (15000), `DC_SHARD_MIN` (1000), `DC_SHARD_FACET_MIN_COVERAGE` (0.8); raise `DC_MAX_PLACES` default → 150000 AND its field bound `le` → 1000000 (C1); add `model_validator` `shard_min ≤ shard_size ≤ max_places` (M4).
3. Generalize the file path to a page-producer (Decision 2) + `_finalize_file_result`; reuse for both single-fetch and sharded. Add `places_missing` to `ObservationsFileResult`.
4. Sharded page-producer: enumerate → spread-sample facet probe → shard loop (adaptive `fetch_shard` halving on 500/502, write each leaf) → per-shard build → yield. Coverage guard → `places_missing`.
5. Single service-level orchestrator (Decision 4): enumerate once → dispatch refuse | shard | A-i.
6. Remove ONLY the dead `next_token` loop + `_write_api_response_page` (M1); keep `_stream_to_file`.
7. Tests + `docs/reference.md`.
8. Gate: ruff + mypy + full suite + coverage ≥ 80; a live manual sanity export of a beyond-single-request geography if a key is available.

**Rollback:** revert; new path is additive (the ≤ `DC_SHARD_SIZE` path is unchanged), so reverting restores the refusal behavior for big queries.

**Apply MUST confirm (from Gate 1):** (a) a 502 surfaces as `DCStatusError`, not a raw `requests.Timeout` that escapes the lib's catch (I4 — widen if needed); (b) per-shard `_fetch_all_metadata` is acceptable vs one upfront names fetch (likely fine — bounded per shard); (c) the page-producer generalization of `_handle_file_output` preserves every existing `ObservationsFileResult` field (preview/summary/columns/format/multi_file/sizes).
